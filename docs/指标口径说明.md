# 指标口径与证据分级说明

本文档规定应用输出的每个数字的含义、分母与禁止的解释方式。所有指标仅基于本地合成资料。

## 1. 分层单位

- 条件 = 佩戴（`none`/`hat`/`sunglasses`/`both`）× 照明（`day`/`dusk`/`night`），
  由分类法版本决定如何归并（见 `taxonomy.py`）。
- 会话（session）是最小资料单元；同一 `driver_key` 可拥有多段会话，属于重复测量。

## 2. 提示率（系统行为，不是注意力缺失率）

| 指标 | 计算 | 说明 |
| --- | --- | --- |
| `prompt_rate_per_hour` | 条件内 `sum(prompt_count) / sum(task_minutes) × 60` | 全部会话口径 |
| `prompt_rate_observable_per_hour` | 仅 `camera_state=available` 会话的同式计算 | 没有可用摄像头会话时为 `null`（无法评估），不填 0 |
| `sessions_with_prompt_ratio` | 至少出现 1 次提示的会话占比 | 辅助判断提示是否集中在少数会话 |
| `driver_level_prompt_rate_mean` | 先按驾驶员计算各自的每小时提示率，再对驾驶员取平均 | 避免高频会话驾驶员主导整体值 |

**禁止解释**：不得把提示率写成「注意力缺失率」。提示是系统输出，注意力是否缺失只能由
人工复核标签（且 `unclear` 不等于 `away`）等证据辅助判断。

## 3. 不可观测比例（信号缺口，不是未注视道路）

- `unobservable_sessions`：`camera_state ∈ {occluded, unknown}` 的会话数。
- `unobservable_ratio = unobservable_sessions / sessions_total`。
- `camera_breakdown` 同时给出三种摄像头状态的明细。

**禁止解释**：不可观测只表示系统没读到眼部信号。报告必须保留护栏语句
「不能直接判定驾驶员未注视道路」。V15 宣称改善帽子/太阳镜场景可用性时，
应比较 V14/V15 在相同条件下的不可观测比例与仅可用摄像头会话的提示率，
而不是比较总提示数。

## 4. 反馈覆盖（自愿样本，禁止外推）

| 指标 | 计算 |
| --- | --- |
| `feedback_coverage` | 条件内有反馈的会话数 / 会话总数 |
| `feedback_driver_coverage` | 有反馈的驾驶员数 / 条件内驾驶员数 |
| `rating_mean_respondents_only` | 仅回复者评分均值；无回复为 `null`，不是 0 |
| `consent_scope_breakdown` | `retention-ok` 与 `research-only` 的回复数量 |

**禁止解释**：未回复用户的体验未知，不能假设其与回复者相同。覆盖低于阈值
（默认 30%）时报告自动追加「评分仅代表少数回复者」护栏。

## 5. 人工复核与一致性

| 指标 | 计算 |
| --- | --- |
| `review_coverage` | 被至少一条标注覆盖的会话数 / 会话总数 |
| `label_distribution` | `attentive`/`away`/`unclear` 计数 |
| `unclear_label_ratio` | `unclear` 占全部标注比例；`unclear` 是待澄清状态，不并入 `away` |
| `double_annotated_sessions` | 拥有 ≥2 条标注的会话数 |
| `annotation_pair_agreement` | 同会话标注两两成对的标签一致比例；无成对样本时为 `null` |

**禁止解释**：没有双注样本时一致性是「无法评估」，不得报告为「100% 一致」或「已验证一致」。

## 6. 版本拆分

每个条件同时输出 V14/V15 各自的会话数、驾驶员数、提示率、不可观测比例，
用于在相同佩戴/照明条件内对照版本差异，避免跨条件比较造成的混杂。

## 7. 证据分级规则（默认阈值，可调）

规则集中在 `metrics.EvidenceRules`：

| 阈值参数 | 默认值 | 含义 |
| --- | --- | --- |
| `min_sessions` | 8 | 条件最少会话数 |
| `min_distinct_drivers` | 4 | 条件最少不同驾驶员数 |
| `max_unobservable_ratio` | 0.4 | 超过则判定信号缺口过大 |
| `min_feedback_coverage` | 0.3 | 低于则判定选择性反馈不足 |
| `min_reviewed_sessions` | 3 | 最少复核片段 |
| `min_agreement_pairs` | 2 | 评估一致性所需的最少双注会话 |
| `min_agreement` | 0.8 | 最低成对一致比例 |
| `max_unclear_label_ratio` | 0.25 | 超过则需复核澄清 |

判定顺序：

1. 无会话 → `unknown`；
2. 样本量或反馈覆盖不达标 → `needs_research`（根本缺口，靠复核无法弥补）；
3. 其余任一复核/不可观测/一致性/标注清晰度问题 → `needs_review`；
4. 全部达标 → `sufficient`。

每次分析都会把完整指标哈希（`data_hash`）写入证据快照，分级原因逐条留痕，
便于事后回答「为什么这个条件当时被判为未知/需复核」。
