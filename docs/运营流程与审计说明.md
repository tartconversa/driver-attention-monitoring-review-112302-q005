# 运营流程与审计说明

## 1. 角色与职责

| 角色 | 在应用中的动作 |
| --- | --- |
| 数据工程 | `import` / `watch` 持续导入会话、反馈、标注、名额资料 |
| 分析人员 | `analyze` 生成证据快照；维护分类法与分级阈值 |
| 体验负责人 | `decision add` 登记「继续观察 / 调整产品说明 / 申请针对性研究」 |
| 研究协调员 | `plan create` 安排同意参与者、任务与设备；`slot execute/withdraw/device-fail` |
| 标注员 | 产出 `annotations.csv`（应用只读取，复核结论以标注记录为准） |

## 2. 持续导入

- 输入 CSV 永远只读；应用状态写入独立的状态库目录（`state.json` + `journal.jsonl`）。
- 每行按**内容哈希**去重：同一文件重复导入全部跳过；同主键但内容变化会被拒绝，
  防止静默覆盖历史资料。
- `watch` 按目录指纹轮询，只在四个 CSV 任一内容变化时触发一次导入，
  适合对接定时落盘的脱敏资料管道。
- 整批校验（受控词表、类型、外键引用、重复主键）通过后才写入，任一行不合规则整批拒绝。

## 3. 证据快照与决策追溯

- 每次 `analyze` 为当前分类法下每个条件生成一条 `current` 证据快照，
  含完整指标、分级原因与指标哈希。
- 与上一版 current 快照比较，关键指标变化会：
  1. 在新快照原因中记录差异；
  2. 把相关条件上的既有决策自动标记 `affected_by_change=true`，
     提醒负责人确认原决策是否仍然成立。
- `trace <条件>` 汇总该条件的快照链、决策链与研究计划，直接回答：
  - 为什么仍属未知（快照分级原因逐条列出）；
  - 研究计划由谁接受（`accepted_by` / `accepted_at`）；
  - 哪些决策被新结果影响（受影响标记）。

## 4. 分类法版本管理

- v1：4 佩戴 × 3 照明 = 12 条件；v2：`dusk`/`night` 合并为 `low_light`，
  佩戴命名规范化，共 8 条件。
- 启用新版本（`taxonomy activate`）时：
  - 所有旧 current 快照标记为 `superseded` 并记录指向的新条件；
  - 自动生成 `carried_over` 占位快照，保留旧证据但明确「待复核确认」；
  - 多对一合并（如 dusk、night 并入 low_light）的旧结论**不会**自动升级为最终结论。
- 决策必须引用同分类法版本下存在的快照，防止跨版本误引用。

## 5. 研究名额生命周期

```
open ──plan accept──▶ accepted ──slot execute──▶ done
  │                     │
  │                     ├──slot withdraw──▶ withdrawn（释放未执行容量）
  │                     └──slot device-fail──▶ device_failed（释放未执行容量）
  └──slot withdraw / device-fail（同上）
```

业务规则：

1. **接受计划才占用名额**：`plan create` 不消耗任何名额；`plan accept` 只允许占用
   `open` 且同意未撤回的名额，重复占用被拒绝。
2. **执行前必须有有效同意**：`pending`/`withdrawn` 同意的名额不能执行。
3. **撤回同意**：
   - 名额未执行 → 名额转 `withdrawn`，容量计入计划的 `released_capacity`；
   - 名额已执行 → 名额状态不变、容量不释放；已采集资料按**原授权范围**处置：
     `research-only` 转 `removal_pending`（随后可 `material remove` 物理移除），
     `retention-ok` 保留。
4. **设备失效**：只能释放未执行名额；已执行名额的资料不受影响。
5. 撤回后该名额同意状态同步为 `withdrawn`，无法再采集新资料。

## 6. 审计日志（哈希链）

- 每次状态变更先向 `journal.jsonl` 追加一条记录，再物化 `state.json`。
- 每条记录包含 `seq`、时间戳、操作人、动作、载荷、前驱哈希与自身哈希；
  自身哈希由前驱哈希与本条内容共同决定，任一条目被篡改都会导致
  `verify` 校验在对应行号失败。
- 重新打开状态库时自动校验哈希链，校验失败则拒绝加载。
- 输入资料不进日志载荷，日志只记录来源目录与导入摘要，避免把明细复制到第二处。

## 7. 合成数据与测试

- `synthdata.py` 使用固定随机种子，刻意制造：条件冷热不均、夜间困难条件不可观测偏高、
  约三分之一反馈覆盖、4 个双注片段（含 1 处分歧）、齐全的名额/同意状态组合。
- 同种子两次生成的文件字节一致，可用于可复现演示。
- `tests/` 共 43 个用例，覆盖：导入校验与幂等、指标口径与护栏、分级规则、
  版本切换与适用范围重标、名额生命周期与授权处置、轮询导入、端到端决策追溯、
  审计链防篡改。
